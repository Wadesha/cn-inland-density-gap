# 内陆高密度 · 低发展区带 · 交互地图

一个面向「胡线以东内陆、人口密但发展弱」区带的可视化站点。三级钻取：省级入口 → 县级双变量填色 → 单地详情页。

---

## 1. 项目定位与核心命题

### 研究对象（严格限定）
- **只看「人口密、发展弱」**：高密度 + 低发展指数的内陆区县。
- **地理范围**：胡焕庸线以东的内陆（不含沿海地级市）。
- **明确排除**（用户硬要求，勿 reintroduce）：
  - 稀疏侧（青海/新疆/西藏等）—— 数据集里根本没有低密度区县；
  - 胡焕庸线「东南/西北分界」宏观框架 —— 命题全在该分界内部，提它无意义；
  - 省份 / 大区 粗粒度 —— 用户要求**县 / 流域盆地级**细粒度。

### 核心机制（这是本项目的「为什么」）
人口的「密」与现代化的「发展」是**两条不同的因果链**，被习惯性地当成一条：

1. **人口密度的自然成因 = 农耕承载力的空间投影。**
   华北平原、成都平原、江汉平原等内陆高密度区，密是因为：平坦冲积土 + 有水或可灌 + 积温够两熟。古人能养活多少人取决于「一平方公里能打多少粮」，不是「能造多少附加值」。所以密度是自然的、农业的变量。
2. **发展指数（现代意义）= 非农附加值的人均占有。**
   它偏爱贸易可达性（港口/枢纽）、产业结构（工业/服务占比）、人力资本。平坦肥沃的农田恰好不构成这些优势，甚至可能构成**农耕锁定**：土地太能养人，反而把劳动力钉在农业上，抑制工业化和人均收入。

→ 「密而弱」不是矛盾，是**两套尺度的错配**：密度量「能养多少人」，发展量「每人创造多少非农业价值」。**县尺度下这个错配才看得清**——省平均会把密集农业县和密集工业县抹平。

### 分析风格偏好（写入 ~/.workbuddy/MEMORY.md，跨项目生效）
- 反对宏观大颗粒度（胡线/省份/大区）作为默认视角；
- 偏好**县 / 流域盆地级**细颗粒度，从最基础的「自然/地理/环境」基本面出发做辩证分析，而非盲从既有理论；
- 命题若全落在某一宏观分区内部，就不要再提该宏观分界本身。

## 2. 展示结构（三级钻取，避免一次性加载 26MB 全县界）

| 页面 | 作用 | 加载的几何 | 说明 |
|---|---|---|---|
| `index.html` | 省级入口 | `provinces.geojson`（~1.3MB，省级轮廓） | 颜色越红 = 该省抽样的「密而弱」区县越多；点击省进入 |
| `province.html?code={省adcode前2位}` | 本省县级双变量填色 | `provinces/{pp}.geojson`（~0.5–1.5MB，该省所有县市多边形） | 红=密而弱，蓝=密而强；灰底=样本未覆盖；点击区县进详情 |
| `place.html?name={区县名}` | 单地详情页 | `provinces/{pp}.geojson`（画省内迷你图） | 双变量矩阵定位 / 指标卡 / 自然条件 / 机制 / 同省强对照 |

> 参数 `code` 取省 adcode 前两位（豫=41，皖=34，鲁=37，冀=13，苏=32，鄂=42，湘=43，川=51，陕=61，赣=36）。`name` 为区县全称，需与底图 `properties.name` 完全一致（如 `临泉县`/`周口市`）。

## 4. 数据模型（`data.json`）

数组，每项一个区县：

```json
{
  "name": "周口市",      // 必须与底图 properties.name 完全一致
  "prov": "豫",          // 省份单字（用于 index 按省计数、place 反查前缀）
  "dens": 800,           // 人口密度 人/km²
  "dev": 35000,          // 人均GDP 元（发展指数的当前代理指标）
  "type": "poor",        // "poor"=密而弱（重点） / "rich"=密而强（同内陆对照）
  "nat": "黄淮平原·两熟" // 自然条件标签（密度之因）
}
```

- 当前为**示意样本**（量级近似，非精确统计），覆盖 10 个内陆省份约 60 个区县。
- 几何已覆盖**全国所有县**，因此**扩数据只需改 `data.json`，前端零改动**。

## 5. 双变量配色方案（3×3）

横轴=人口密度（低·中·高），纵轴=发展指数（低·中·高）。颜色矩阵 `MATRIX[devTier][denTier]`：

| 发展＼密度 | 低 | 中 | 高 |
|---|---|---|---|
| **低**（弱） | `#6b3a3a` | `#a84545` | **`#ff5a5a`（密而弱·重点）** |
| **中** | `#7a6a3a` | `#b08a3a` | `#e0b03a` |
| **高**（强） | `#3a6b5a` | `#3a8a7a` | `#4aa3c0`（密而强·对照） |

分档阈值（在三个 HTML 的 JS 顶部常量）：
- 密度：`DEN_LOW=450`，`DEN_MID=700`（人/km²）
- 发展：`DEV_LOW=50000`，`DEV_MID=80000`（元）

> 红=高密低发展（用户关注的核心），蓝=高密高发展（证明密度不注定贫困）。

## 6. 几何数据来源与生成

底图来自 **阿里云 DataV GeoAtlas**（`geo.datav.aliyun.com/areas_v3/bound/{adcode}_full.json`）。

### 关键事实（避免重踩）
- DataV 的 `{省}_full` **只返回下一级**（省→市），不含县。要拿县必须**两级抓取**：省 `_full` 拿市，再对每个市 `_full` 拿县。
- 因此 `fetch_counties.js`：遍历 34 省 → 取市特征（level=city）→ 再遍历各市 → 取县特征（level=district）。结果 3177 要素（2814 县 + 363 市），原文件 `china-counties.geojson`（26MB，本地保留，未部署）。
- `build_geo.js`：按 adcode 前两位把全县界拆成 `provinces/{pp}.geojson`；并另抓 `{pp}0000.json` 合成 `provinces.geojson`（省级轮廓）。

### 本地生成命令（如需重建几何）
```bash
node fetch_counties.js     # 爬全县界 → china-counties.geojson
node build_geo.js          # 拆分 → provinces/ + provinces.geojson
```

- **仓库**：`Wadesha/cn-inland-density-gap`（public）
- **站点**：https://wadesha.github.io/cn-inland-density-gap/

- **Token 安全（硬规则，违反即泄露）**：
  - Token 存于本地 `~/.workbuddy/MEMORY.md`，**绝不写进任何会被提交/部署的文件**，不进 git 历史、不进 commit message、不回显；
  - `deploy.js` 运行时从 `~/.workbuddy/MEMORY.md` 正则读取（`ghp_[A-Za-z0-9]+`，取 `[0]` 非 `[1]`），仅放进 `Authorization: token <TOKEN>` 头；
  - 上传前先 `GET` 取 `sha`（已存在文件需带 sha 才能更新）。

### 部署命令
```bash
node deploy.js
```
（会遍历 index/province/place/html、data.json、README.md、echarts.min.js、provinces.geojson 及 provinces/ 下所有 .geojson 并上传；Pages 已启用则返回 409，正常。）Pages 重建约 1 分钟，期间新文件可能短暂 404。

## 8. 已踩坑 / 关键修复（务必记牢，避免重犯）

1. **境外 CDN 国内不可达**：原 `index.html` 引 `cdn.jsdelivr.net` 的 ECharts，国内被墙 → 整图空白。已改为**本地 `echarts.min.js`**（从 `registry.npmmirror.com` 拉取后入库）。面向国内用户的静态站，禁用 jsdelivr/unpkg，依赖务必本地化或走 npmmirror 等国内源。
2. **ECharts 地图填色属性**：`series.type:'map'` 区域填充必须用 **`itemStyle.areaColor`**，误用 `itemStyle.color`（仅散点/折线有效）会导致所有区县退回默认灰底、看起来「抽样不上色」。三处地图（index/province/place）均已改为 `areaColor`。
3. **市/县多边形重叠 + 渲染顺序**：数据里「市级样本」（如周口市）与其下「县级多边形」重叠；县默认画在市之上，灰色盖住红色，导致市级样本整片看不见（河南一度只显 2 个县）。修法：`province.html` 把市级样本按 **adcode 前 4 位前缀**下钻着色到其下每个县（`effOf`），并 `geo.features.sort` 让市多边形置于县之下。实测河南 156 县中 85 被着色。
4. **DataV 层级**：见 §6，县界需两级抓取，别再用 `{省}_full` 当县界。

## 9. 如何更新 / 扩充（给后续接手）

### A. 增补样本区县（最直接）
编辑 `data.json`，按 §4 字段加项。**几何已覆盖全国所有县，前端无需改动**。加完跑 `node deploy.js`。

### B. 扩到全县覆盖（让腰带真正铺满）
- **方案 A（快，近似）**：把 10 个内陆省所有区县用近似值批量补进 `data.json`，地图立刻填满，仍标「示意」。
- **方案 B（准，工程大）**：接真实数据——七普人口密度 + 统计年鉴县级人均GDP / 非农就业占比。需逐县取数，但精确。

### C. 发展指数换定义（当前用「人均GDP」）
候选：
- A 人均GDP（现状，最硬）；
- B 类HDI（收入+预期寿命+受教育）；
- C 复合现代化指数（非农就业占比+工业化率+基建+收入）；
- D 卫星夜间灯光（NTL）作实际经济活动代理。
切换只需改三处 HTML 顶部阈值常量与 `MATRIX` 取值来源；建议先把 C 做成可切换维度。

### D. 加横切视图（不破坏钻取）
在省级入口之上叠加全局分析视图：
- **背离指数排行**：密度百分位 − 发展百分位，残差越大越「不该穷却穷」；
- **机制分型**：农业锁定 / 山区封闭 / 劳务输出留守 / 老工业衰退；
- **地形小倍数图**：按平原/丘陵/盆地/山前分面；
- **时间演化**：2000→2020 缺口是收窄还是扩大。
